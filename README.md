# לוח בקרה למלאי ולוגיסטיקה

מטלה 4.4 בקורס AiDO, שיעורים 3 ו-4: דאשבורד מלאי ולוגיסטיקה על נתוני דמה, שנקראים מבסיס נתונים ב-Airtable.

**האתר:** https://yossisoudry.github.io/logistics-dashboard/

- [SPEC.md](SPEC.md) – האפיון: מי, מה ומה לא, איפה, פיצ'רים, ומה נחשב "גמור".
- [Practice.md](Practice.md) – איך עובדים על הפרויקט: סקירה, תוכנית, בנייה, בדיקות, קומיט.

## הסטאק

Vite, React, Tailwind ו-[shadcn/ui](https://ui.shadcn.com) במצב RTL, בערכת הצבעים Twitter של [tweakcn](https://tweakcn.com).

## נתונים מ-Airtable

הלוח קורא את הנתונים מבסיס Airtable בכל כניסה, ולא מקובץ סטטי. ארבע טבלאות עם קשרים ביניהן: `Warehouses`, `Contractors`, `Inventory`, `Shipments` (פירוט ב-[SPEC.md](SPEC.md#נתונים)).
בכותרת מופיעים מקור הנתונים, שעת העדכון וכפתור רענון: משנים רשומה ב-Airtable, לוחצים רענון, והשינוי מופיע.

**הקמה:**
1. ב-Airtable: יוצרים בסיס ריק ושני טוקנים ב-[Builder Hub](https://airtable.com/create/tokens), שניהם לבסיס הזה בלבד:
   - טוקן קריאה לאתר: `data.records:read`.
   - טוקן כתיבה לטעינה: `data.records:read`, `data.records:write`, `schema.bases:read`, `schema.bases:write`.
2. מעתיקים את `.env.example` ל-`.env` וממלאים (הקובץ לא נכנס ל-git).
3. `pnpm seed -- --dry-run` (חזרה גנרלית, בלי לכתוב), ואז `pnpm seed`: יוצר את הטבלאות ואת הרשומות החסרות, סופר נכנס ויוצא, ובודק שהלוח קורא בדיוק את הקובץ. בטוח להרצה חוזרת, ולא דורס עריכה שנעשתה ב-Airtable (רק `--restore` מחזיר את נתוני הדמה). כל הרצה נרשמת ב-`logs/`. אחרי הטעינה אפשר למחוק את טוקן הכתיבה.
4. ב-Vercel, בפרויקט `logistics-dashboard-api`: משתני הסביבה `AIRTABLE_BASE_ID` ו-`AIRTABLE_READ_TOKEN`, ו-`DEMO_NOW=2026-11-08T18:00:00` (ה"עכשיו" של הדמו; בלעדיו הלוח לפי השעון של השרת). הם נשארים בשרת. האתר ב-GitHub Pages נבנה בלי שום טוקן.

**אבטחה:** הדפדפן לא פונה ל-Airtable. הוא פונה לפונקציה אחת ב-Vercel (`api/dashboard.js`), שמחזיקה את טוקן הקריאה, קוראת מ-Airtable ומחזירה רק את הנתונים. כל מה שנמצא בקוד האתר גלוי לכל מי שפותח אותו, ולכן הטוקן לא שם.
הפונקציה עונה רק לקריאה (GET) ורק לאתר ב-GitHub Pages או ל-localhost. אחרי כל בנייה, `pnpm check:bundle` סורק את קוד האתר ועוצר את הפרסום אם יש בו טוקן או כתובת של Airtable.

## מקור מידע חיצוני: Hebcal (משימת בונוס)

כרטיס "עד כניסת שבת" בסקירה: לכל מחסן, הדלקת הנרות הקרובה בעיר שלו, כמה זמן נשאר מ-"עכשיו", וכמה משלוחים עוד פתוחים לפניה. ערב חג מזוהה לפי סימון יום טוב של Hebcal.
- המקור: [Hebcal](https://www.hebcal.com/home/developer-apis), API ציבורי, חינמי ובלי מפתח, רישיון CC BY 4.0.
- הדפדפן לא פונה ל-Hebcal. הפונקציה `api/shabbat.js` ב-Vercel בודקת את הקלט, קוראת מ-Hebcal, בודקת שהתשובה בפורמט הצפוי ומחזירה חוזה קצר משלנו. הזמנים של שבוע לא משתנים, ולכן התשובה נשמרת שש שעות.
- העיר של כל מחסן היא עובדה שלנו, ולכן היא בטבלת `Warehouses` ב-Airtable (`City`, `Geoname ID`).
- הבדיקות רצות מול תשובות אמיתיות של Hebcal שנשמרו ב-`test/fixtures/`. אם Hebcal לא זמין, רק הכרטיס אומר זאת.

## הרצה מקומית

```
pnpm install
pnpm dev
```

## בדיקות ובנייה

```
pnpm test
pnpm build
```

הבדיקות ב-`test/` נגזרות משורות ה"גמור" ב-SPEC.md. הן רצות עם `node --test` על הלוגיקה הטהורה:
`src/logic.js` לנתונים, `src/lib/theme.js` למצב הבהיר והכהה, `src/lib/routes.js` לניווט, ו-`src/lib/airtable.js` עם `src/lib/airtable-client.js` להמרה ולקריאה מ-Airtable (עם fetch מדומה, בלי רשת).
